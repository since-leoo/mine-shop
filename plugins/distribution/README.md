# 分销推广插件

插件包：`since/distribution`。后台入口：插件中心 → 分销推广 → 管理 / 佣金设置。

异常中文文案与业务码集中维护在 `app/Infrastructure/Error/DistributionError.php`（`410xxx`），保留领域、参数和内部异常类型。后台拒绝访问仍返回原 `FORBIDDEN` / `DISABLED` 状态，独立 `error_code` 标识具体原因。微信分享失败返回集中中文提示和本地业务码，微信原始 `errcode` / `errmsg` 仅保存在 previous 异常链中用于日志诊断；框架 `ValidationException` 继续使用验证器消息。

## 启用与部署

插件随代码安装，**业务默认关闭、默认佣金比例为 0**。先在目标环境完成迁移和微信配置，再在后台保存规则并开启分销。`install.lock` 仅代表插件代码已安装，不能替代数据库迁移。

```sh
php bin/hyperf.php migrate
```

标准迁移命令通过现有 `InstalledPluginMigratorFactory` 发现插件内迁移，只创建 `distribution_*` 业务表。首次完成时间记录在插件订单快照表中，不给核心订单表增加分销字段。后台直接从插件中心加载页面，不写 `menu` 表，也不需要权限 Seeder；当前分销管理接口默认仅有效超级管理员可访问。

前端安装依赖并构建：

```sh
cd web
npm install
npm run build
```

```sh
cd miniprogram
npm install
npm run build:h5
npm run build:weapp
```

重新加载后端服务、交易恢复任务和定时任务，使新增路由与依赖生效。确保原交易 Outbox 消费/恢复任务及分销定时结算任务正常运行。

- 在分销设置配置正式 H5 根地址，例如 `https://shop.example.com`，用于跨端复制 H5 邀请链接。
- 小程序二维码、短链、URL Link 使用已有微信插件配置与账号权限；微信接口失败会返回明确提示，不伪造短链。
- 微信小程序需先发布包含 `plugins/distribution/pages/landing/index` 的版本，再启用无限二维码；默认校验正式版页面。需配置后端请求/图片下载域名。二维码缓存写入 `public/uploadfile/wechat/mini/qrcode`，后端需具备目录写权限。
- 沿用商城现有的 H5 / 小程序认证与会员身份模型，分销不改造登录、不自动合并已有账号。插件只在新会员注册事务内处理邀请归因。
- 提现为**人工审核、人工打款、登记真实打款流水**，未对接微信商家转账或银行代付。

## 插件边界

- 后端规则、数据迁移、路由、注册接入、交易监听、分享适配、后台管理页面全部位于 `plugins/distribution`。
- H5 / 小程序页面、分享、邀请来源、用户中心扩展全部位于 `miniprogram/src/plugins/distribution`；宿主只调用通用生命周期、认证、分享与展示扩展接口，并聚合插件导出的页面路由。
- 后台 `web/src/plugins/since/distribution/index.ts` 只有标准插件加载用的重导出，业务页面在插件包内。
- 核心保留的接入仅为公共注册/订单事件：`MemberRegistered`、`OrderSubmissionPreparing`、`OrderPersisted`、`OrderCompletedEvent`。已有支付/退款事件被插件监听，主订单服务不依赖分销类、分销契约或分销表。
- 新增通用订单准备/持久化事件同步执行；佣金快照与订单写入同事务。确认收货和自动收货复用公共完成 Outbox，插件记录自身冻结期起点。

## 关系与分享规则

- 沿用会员唯一邀请码、`members.referrer_id`；每人最多 3 个直属成员，团队包含全部层级后代，不含本人。
- 只有真正的新会员注册时绑定。已注册会员再次扫码或访问分享链接不会换上级。无来源、无效来源、邀请人名额已满均完成注册并归属平台；名额已满会返回明确提示。
- 不自动向下排位、不替换旧上级、不因退款释放邀请名额。历史已存在的关系保留；历史超过 3 人的节点不再接收新直属成员。
- 前端保存第一个有效邀请来源 7 天，服务端分享 token 有效期 30 天；最终以注册事务内校验为准，行锁控制并发名额。
- 分享 token 由服务端根据当前登录会员签发，URL 中的任意用户 ID 不能用于绑定。商品分享保留商品、SKU、活动及拼团参数。
- 主动分享生成当前会员的归因；直接转发原链接仍归原分享者。邀请码、H5 链接/二维码、小程序卡片/二维码/短链/URL Link 共用同一绑定规则。

## 佣金与账务

第一期固定为**直属一级销售佣金**，团队统计不代表对全部祖先发佣金。

- 规则优先级：排除商品 → SKU 特定规则 → 商品规则 → 全局比例。商品规则支持按比例或按件固定金额，佣金不超过该行可计佣金额。
- 金额使用整数分；比例使用基点，`100 = 1%`。按优惠后商品实付金额计佣，不含运费；当前订单系统没有逐行优惠分摊字段，按商品原金额权重分摊订单商品实付金额，累计舍入保证总额一致。
- 活动商品默认不计佣，可在设置打开。支持全部合资格订单 / 首笔合资格已支付订单两种模式。
- 首单按实际支付时间、订单 ID 判定，不按 Outbox 到达先后判定。没有佣金快照的零佣金、排除商品或关闭期间订单不占首单资格；已获得资格的订单退款后不释放资格。
- 下单时固化受益人、规则版本、商品行金额及结算期；更改规则或业务关闭不追溯修改旧快照。
- 支付后记待结算；确认收货后等待 `max(分销冻结天数, 下单时商城售后天数)`。进行中的售后继续冻结，定时任务按订单独立处理失败。
- 成功退款按商品行累计金额反算佣金扣回，支持部分退款、重复/乱序通知及全额退款。待结算佣金扣待结算；已结算佣金先扣可用余额，不足记录待抵扣欠款，后续佣金优先抵扣。
- 提现申请冻结余额；同会员同请求号幂等，最多一笔进行中申请。状态为待审核 → 已批准 → 已打款，驳回或打款失败释放余额。有退款欠款时禁止标记打款。
- 资金变动产生唯一业务号流水，提现审核、规则变更有操作日志。超级管理员可查看后台收款账号，用户端记录展示脱敏。

## 业务关闭与 DIY

业务开关保存在服务端；H5、小程序显示开关及 DIY 组件开关只控制展示。个人中心右侧邀请码/二维码、DIY 的分销中心卡片均受这些开关控制。关闭新增业务后不再生成新邀请归因和佣金快照，已有会员关系及历史结算、退款、提现继续保留。

曾启用财务业务或已有业务记录的插件不支持物理卸载，`--force` 也不能绕过。请通过插件设置关闭新增业务，保留处理历史账务的能力。未使用的空插件允许卸载。不要直接删除插件目录或修改插件加载开关来代替业务关闭。

DIY 可配置分销标题及邀请、团队、订单、佣金入口显隐；发布内容不保存会员资料、邀请码、佣金余额等私有数据，运行时通过本人接口读取。

## 查询口径与权限

- 直属人数、团队人数和账户余额是当前累计状态；消费统计可按日期过滤。
- 消费金额为支付额扣成功退款金额；有效订单数不包含全额退款订单。
- 团队列表可查看成员自己的消费，也可查看该成员的下级团队消费；个人接口只允许查询本人及后代范围。
- 粉丝订单展示简易商品、状态、金额与脱敏订单号，不返回收货人、地址、手机号。
- 插件自有后台中间件要求有效超级管理员；普通后台账号不能查询分销数据或审核提现，不向主项目菜单/权限表写入记录。

后台接口前缀 `/admin/distribution`，用户接口前缀 `/api/v1/distribution`。所有分销路由，包括 `/status`、`/share/resolve`，都由插件提供。未安装或未加载时这些路由不存在，前台通用扩展允许插件静默缺席；业务关闭时插件仍加载以处理历史账务。
