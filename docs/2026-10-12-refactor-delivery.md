日期：2026-10-12。本轮按确认范围实现经营分析、DIY 装修、商品评价三个插件，客服第二版及交易基础修复。优惠券、秒杀、拼团、会员营销和支付渠道的独立插件化留待后续。

详细说明：[客服配置、路由和 AI](../plugins/customer-service/README.md)、[客服前端与浏览器回归](../plugins/customer-service/web/README.md)、[交易修复与并发测试](../tests/Integration/Trade/README.md)。

## 项目评估与拆分边界

项目已有 Hyperf、DDD 分层、订单策略和插件启动机制，可以按能力拆分，无须重建订单内核。当前优先事项是保证插件停用后核心可运行、交易失败能够恢复，以及配置保存后在实际业务中生效。

| 模块 | 本轮处理 | 核心边界 |
| --- | --- | --- |
| 经营分析 | 独立 `plugins/analytics`，迁移分析、报表、聚合与后台界面 | 交易事实与基础待办留在核心，分析停用可降级 |
| DIY 装修 | 独立 `plugins/diy`，迁移页面、模板、发布、选择器与后台实现；小程序渲染归入自己的插件目录 | 商品、券、活动数据通过 `DiyCatalogDataSourceInterface` 查询；保留基础首页 |
| 商品评价 | 独立 `plugins/product-review`，迁移评价、审核、回复及统计 | 核心通过 `ReviewEligibilityInterface` 提供订单资格；商品与订单通过评价能力接口交互 |
| 系统通知 | 增加可选接口适配 | 订单、库存监听器不再静态调用消息插件；停用时使用空实现 |
| 客服 | 保持一个插件，内部拆分类目、关键词、分配、AI、配置与传输能力 | 通过接口连接 AI Provider、知识检索、配置存储、事件发布、连接凭据、授权和在线状态 |
| 交易 | 修复支付、余额、异步下单、取消、退款和恢复任务 | 支付账、退款账、订单和库存仍由核心维护 |

`OptionalCapabilityFactory` 只解析已加载插件 Provider 声明的 `plugin_capabilities`；核心定义 Contract 和降级实现。新插件保留原 URL、权限码及表名。后台采用插件目录作为唯一实现源码，原路径保留适配入口。

按全新部署要求，三个插件的原始建表迁移已移入各自 `Database/Migrations/`，保留原日期与文件名，删除接管包装和重复来源。`install.lock` 仅表示插件代码已安装，数据库是否执行迁移由 `migrations` 表判断。标准迁移命令现在自动发现已安装插件的目录，兼容 `Database/Migrations` 和 `migrations` 两种约定；显式 `--path` 仍只执行指定目录。

### 全新部署迁移调整

- 客服第二版字段和表直接进入原始客服建表迁移，权限定义进入原始菜单种子，删除本轮历史数据补齐和权限回填迁移。
- 下单恢复记录、交易 outbox 直接进入原始订单迁移；退款状态直接使用最终定义，删除本轮交易增量迁移。
- 消息中心缺表的原因是插件目录没有进入标准迁移路径，且安装器原先不识别小写目录。现已修正发现机制；消息、收件人、模板、偏好、投递日志一次建齐。
- 消息结构补齐代码已使用的 `extra_data` 和投递渠道；本轮涉及的表及所有字段补齐数据库备注，关键状态、权限、幂等、事务与恢复边界补上代码注释。

此次按空库部署维护原始建表文件，不再提供旧库增量升级。已经写入迁移记录的旧库不会因源文件修改而自动补列；需要按全新部署计划初始化所选数据库。没有对正在使用的业务库执行删库、清表或结构修改。

## 客服行为

- AI 默认关闭；开启并发布有效默认 Agent 后，新协议客户端先进入 AI 接待。无可靠知识、请求人工、不支持的消息类型、服务异常或达到限制时进入人工处理。
- 支持 AI 连接、模型、角色说明、知识范围、检索阈值、输出限制、超时、轮次与每日预算。密钥只引用服务端环境变量，不写进配置快照。
- 问题类目最多三级；支持父级继承、强制人工、默认 Agent、技能组、优先级。关键词支持正向词、排除词、匹配方式和冲突处理。
- 人工坐席支持技能范围、技能组、优先级、权重、容量与排班；分配同时检查在线租约。自动分配可选最少负载、轮询、加权负载，也可手动接单。
- 动态设置包含排队、上限、超时、消息限制、图片/商品卡开关、营业时间等。配置可保存草稿、校验发布、回滚、模拟路由；坐席参数单独保存后即时生效。
- 首次部署直接创建完整配置和运行表，不导入旧 FAQ 或坐席数据。禁用技能或组后不再取得对应候选会话的查看、接单资格，已分配会话保留连续接待；关闭排队仍可分配在线坐席。转人工按类目技能组、Agent 备用组、全局备用组的优先级选定已配置目标，再沿该组的备用链匹配客服。
- 保留旧 `status` 字段投影与旧入口；协议第二版增加 `reception_state`、`generation`、消息序号等。旧客户端进入人工链路。
- 消息、会话变化在事务内写 outbox，再由任务发布；客户端使用消息 ID 和游标恢复。转人工、接管、关闭及停用使不再有效的 AI 回复失效。
- Socket 凭据原子消费，每条坐席操作重新检查对应权限；多标签页使用独立在线租约。列表广播只通知刷新，具体消息只投递给授权身份。

配置资源采用不可变版本快照和稳定 ID，而非每类配置各一张可变表。小规模配置可以原子校验和发布，避免半套配置同时生效；编辑有乐观并发控制。会话、消息、知识版本、AI 执行记录与投递事件仍独立存储。

本轮 AI 业务工具只提供当前会员自己的订单状态查询；没有开放执行订单修改、退款等操作。后台原有图片/商品发送占位不作为已完成能力，会员端已有图片、商品卡和 FAQ 行为保留。

AI 响应必须通过结构和知识引用校验；错误或无依据的回复转人工。调用失败、缺少用量字段时按已预留预算保守计入消耗，避免因模型接口不返回 usage 而绕过限制。后台模型测试会调用已配置模型并消耗 Token，界面已明确提示。

## 交易修复

- 微信预支付使用真实订单号、金额和会员 openid；按本地 SDK 实际验签/解密结构归一回调，校验订单、商户与金额，重复通知幂等处理。
- 余额支付校验订单归属、支付开关和累计日限额，在事务内锁定并重读钱包，支付单、钱包和流水一起提交。
- 下单增加持久化提交记录、按业务号幂等的 Redis 库存预占、队列重试与恢复扫描，避免落单成功后因通知失败重复回库。
- 用户、后台和超时取消共用处理链路；与支付互斥，库存与优惠券只释放一次。迟到支付进入原路退款流程。
- 退款先保存申请，外部调用不持有财务事务锁；未知结果按原退款号查询，财务落账和待投递事件原子提交。支付查单、退款待确认、订单与事件由恢复任务推进。

## 全新部署与配置

1. 停止当前应用进程，在部署配置中指向准备好的空库，清理框架生成的容器缓存。执行下面的建表和初始化命令；标准 `migrate` 会包含已安装插件，不需要手动执行迁移 PHP 文件。
2. 核对插件安装状态，随后重启 HTTP、队列、定时任务及客服订阅进程。仅改前端插件开关不会卸载服务端能力。
3. 原始菜单种子创建客服所需权限定义，不自动复制或扩大旧角色权限。为客服角色分配读、接待和回复权限，配置管理员分配 `customer-service:config:manage`，主管按需分配 `customer-service:conversation:manage`。
4. 配置 AI 时，在服务端设置 `CUSTOMER_SERVICE_AI_ALLOWED_HOSTS` 和 `CUSTOMER_SERVICE_AI_<名称>_KEY`，在后台引用对应变量；发布知识、连接和 Agent，再开启 AI 接待。
5. 确保定时任务和 Redis 订阅进程运行；客服任务负责 AI、排队与消息投递，交易恢复任务负责支付查单、退款、下单和交易事件补偿。

```sh
# 在已配置好的空数据库上执行；此处没有删除现有数据库的操作。
php bin/hyperf.php migrate --force
php bin/hyperf.php db:seed --force

# 使用 DIY 插件时初始化默认页面、分类和模板。
php bin/hyperf.php db:seed --path plugins/diy/seeders --force
```

`db:seed` 是初始化命令，根菜单种子会重建菜单，不能作为已有业务库的补丁命令使用。

## 回归方式

本轮增加真实完整部署回归：独立随机空库中执行标准 `migrate → db:seed → migrate`，验证再次执行无待迁移，所有发现的迁移与数据库记录一致，检查权限、消息未读查询、客服 Worker 以及表字段备注。迁移子进程使用私有配置和缓存，设 180 秒超时，避免测试挂起。

迁移整理后的最终后端验收：42 项单元测试 / 142 条断言，65 项集成测试 / 906 条断言，合计 107 项测试、1048 条断言，全部通过、无跳过项。相关 PHP 语法及 `git diff --check` 检查通过。集成使用真实、独立的 MySQL 和 Redis，包含跨进程竞争、插件启停容器加载，以及完整部署后运行时查询。

本轮后端日志位于 `runtime/codex-verification/fresh-unit-final.log`、`fresh-integration-final.log`，JUnit 同目录保存为 `fresh-unit-final.xml`、`fresh-integration-final.xml`。测试服务诊断保留在 `/tmp/mine-shop-tests.aIIewP`；验收后关闭专用服务并清理临时数据库目录。

```sh

# 也可只跑不需要业务服务的单元测试。
```

后台项目已有全量 TypeScript 类型错误，需要单独治理；交付检查同时对照基线、检查本轮模块并执行生产构建。测试覆盖的场景不等于线上环境联调，正式启用渠道还需使用实际服务配置验证。
